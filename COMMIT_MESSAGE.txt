refactor: simplify getOrCreateUsageTracking with upsert pattern

Replace the read-then-insert pattern with a single upsert operation to
simplify the code and reduce potential race conditions when creating
usage tracking records.

Changes:
- Use upsert with onConflict to atomically ensure usage_tracking row exists
- Remove separate read and insert operations
- Simplify error handling by using a single upsert followed by select
- Rely on database defaults for initial values (scans_this_month, total_scans, last_reset_date)

This reduces code complexity and makes the function more atomic, though
the increment_scan_count RPC function already handles row creation, so
this is primarily a code simplification improvement.
