refactor: implement lazy Supabase client initialization

Replace eager client initialization with lazy initialization to prevent
app crashes at module load time when Supabase environment variables are
missing. This improves developer experience and provides better error
messages.

Changes:
- Add getSupabaseClient() function with lazy initialization
- Check environment variables at call-time instead of module load
- Provide detailed error messages listing missing environment variables
- Include setup instructions in error messages
- Add Proxy-based backward compatibility for existing supabase export
- Update storage.ts to use getSupabaseClient() instead of direct export
- Add error handling in getPublicUrl() to gracefully handle missing config

This allows the app to start even if Supabase isn't configured, and
provides clearer guidance when configuration is needed.
