# Database Schema Fix

## Issue
Clerk user IDs are strings like `user_36IAoOrvCH6oMhrKzk8nHS9pqpq`, but the database schema was using `UUID` type, causing errors:
```
invalid input syntax for type uuid: "user_36IAoOrvCH6oMhrKzk8nHS9pqpq"
```

## Solution
Changed all `user_id` columns from `UUID` to `TEXT` to accommodate Clerk's string-based user IDs.

## Migration Steps

1. **Run the migration SQL** in your Supabase SQL Editor:
   ```sql
   -- See supabase/migration_fix_user_id.sql
   ```

2. **Or manually update** your existing tables:
   - Go to Supabase Dashboard → SQL Editor
   - Run the migration script from `supabase/migration_fix_user_id.sql`

3. **Verify the changes**:
   ```sql
   -- Check that user_id columns are now TEXT
   SELECT column_name, data_type 
   FROM information_schema.columns 
   WHERE table_name IN ('users', 'cvs', 'usage_tracking', 'subscriptions')
   AND column_name = 'id' OR column_name = 'user_id';
   ```

## Updated Schema
- `users.id`: Changed from `UUID` to `TEXT`
- `cvs.user_id`: Changed from `UUID` to `TEXT`
- `usage_tracking.user_id`: Changed from `UUID` to `TEXT`
- `subscriptions.user_id`: Changed from `UUID` to `TEXT`

## Notes
- The `cvs.id` and other primary keys remain as UUIDs (generated by the database)
- Only user-related IDs are TEXT to match Clerk's format
- Foreign key constraints are maintained
